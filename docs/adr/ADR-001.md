# ADR-001: verify is verify-only; regeneration is a separate step

**Why it recurs:** the reflexive "improvement" is to make the gate auto-fix or
regenerate on failure. **Decision:** `aahp verify` never mutates state; a regenerating
gate would hide the very drift it exists to detect, so CI failure stays a true signal.
Regeneration is its own step: update `STATUS.md`, run `aahp manifest`, and commit
both. The gate only names that command when it fails.

**Amended 2026-09-28:** the title read "regeneration is a separate /handoff step".
`/handoff` is not an AAHP command (AAHP ships no agent commands, README Section 9.1);
it was a harness slash command used as shorthand, so the title now names the step.
